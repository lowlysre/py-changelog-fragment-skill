# scriv

`scriv` manages a directory of changelog fragments and aggregates them into a changelog file on release. It's a lighter-weight alternative to `towncrier`: no required category list, Markdown fragments by default, and a `scriv create` command that generates the fragment file for you instead of asking you to name it by hand.

## Installation

```bash
pip install scriv
```

With [`uv`](https://docs.astral.sh/uv/):

```bash
uv add --dev scriv
```

For a one-off run without adding it to the project:

```bash
pipx run scriv --help
# or
uvx scriv --help
```

If the project configures scriv via `pyproject.toml` and runs Python below 3.11, install with the `toml` extra so scriv can parse it (Python 3.11+ has `tomllib` built in):

```bash
pip install scriv[toml]
```

## Project layout

The fragment directory is configurable (`fragment_directory` setting) but defaults to `changelog.d/`:

```
pyproject.toml            # [tool.scriv] settings: categories, format, version, etc.
changelog.d/
  20240115_143022_jdoe_fix_timeout.md   # generated by `scriv create`
CHANGELOG.md / .rst          # generated by `scriv collect`, do not hand-edit
```

> [!NOTE]
> `towncrier` also commonly uses a directory named `changelog.d/`. Tell the two apart by the config section, `[tool.scriv]` versus `[tool.towncrier]` in `pyproject.toml` (or `[scriv]` in `setup.cfg`/`tox.ini`), not by the directory name alone.

## Fragment format

Always create fragments with `scriv create`, don't hand-write the filename:

```bash
scriv create
```

This writes a new file named from the current date/time, your Git/GitHub username, and your branch name, then pre-fills it from a Jinja template. If the project defines `categories` (in `[tool.scriv]`), the template includes one commented-out section per category, uncomment the ones that apply and fill in a bullet under each:

```markdown
<!--
### Bugfixes

- Fix connection timeout not being honored when set via environment variable.
-->
```

Delete the HTML comment markers around any section you use; leave unused sections commented out. A fragment with no headers uncommented is a top-level release note with no category.

## Common commands

```bash
# Create a new fragment for the current branch
scriv create

# Preview and aggregate all fragments into the changelog file
scriv collect

# Optionally, publish collected entries as GitHub releases
scriv github-release
```

There's no separate lint/check command; scriv's format is permissive Markdown or reStructuredText prose, so validation is mostly "did `scriv create` run, and is the placeholder text replaced."

## Best practices

- Always run `scriv create` rather than copying an existing fragment's filename, the timestamp and branch name in the filename are how scriv avoids collisions between concurrent PRs.
- Replace the placeholder bullet text, a fragment left as `- A bullet item for this fragment. EDIT ME!` is a fragment nobody wrote.
- Uncomment only the categories that apply to this change; leftover empty category headers produce empty sections in the released changelog.
- Commit the fragment in the same PR as the change it describes.
